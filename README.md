# Audio Normalizer for Jellyfin

Builds a **second audio track** next to each film: dialogue you can hear, explosions that
don't knock you off the sofa. The original file is never modified — the player simply gains
another audio option, and you can switch back whenever you like.

On the test material (an action-film mock-up: quiet centre dialogue, loud LFE explosions):

| Measurement | Source | After |
|---|---:|---:|
| Integrated loudness | −14.7 LUFS | −16.8 LUFS |
| **Quiet-to-loud range (LRA)** | **25.4 LU** | **10.0 LU** |
| Dialogue level | −37.5 LUFS | −16.7 LUFS |
| Explosion level | −14.1 LUFS | −11.7 LUFS |
| **Dialogue-to-explosion gap** | **23.4 LU** | **5.0 LU** |
| True peak | −5.5 dBTP | −1.6 dBTP |

Dialogue came up by more than 20 dB, and the gap between a whisper and an explosion fell
from 23 LU to 5.

## Project status — please read

**What has actually been verified:**

- The entire audio pipeline was run through real ffmpeg on real files, with the results
  measured. The numbers in the table above come from an actual run, not from theory.
- The filter chains are generated by **the plugin's own code** (`FilterChainBuilder`) — it was
  wired into a test harness and its output pushed through ffmpeg. All six combinations of
  engine × channel layout were checked.
- `tools/normalize-library.sh` completed a full cycle on a test library: it created the
  track with the right name, correctly skipped a film whose audio was already even, and did
  nothing on a second run.
- External audio naming rules were read out of the Jellyfin source
  (`Emby.Naming/ExternalFiles/ExternalPathParser.cs`,
  `MediaBrowser.Providers/MediaInfo/MediaInfoResolver.cs`), not guessed.
- Multi-track behaviour was checked on a film with three audio tracks: all three measured in
  one ffmpeg call, two of them normalized into separate correctly named files.
- The plugin compiles with no errors and no warnings.

**What could not be verified:**

The environment this was written in has no access to nuget.org, so the plugin was built
against **stubs** derived from the real Jellyfin 12.1 source (branch `release-12.z`).
Every type signature in use was checked against that source, but a real build against the
official `Jellyfin.Controller` packages has not happened. In other words:

> The audio side is proven in practice. The Jellyfin integration needs to be built and run
> on your own server — small fixes during the first build are possible.

If you'd rather not deal with that, `tools/normalize-library.sh` delivers 80% of the value
with no build at all, right now.

## Quick start with no build

```bash
./tools/normalize-library.sh --dry-run /media/films   # see what it would do
./tools/normalize-library.sh /media/films             # do it
```

Then in Jellyfin: **Library → Scan**. The new tracks appear in the audio list.

Options: `--target -16` (loudness), `--range 9` (allowed spread), `--peak -1.5` (ceiling),
`--codec eac3`, `--bitrate 384k`, `--force`, `--title "Night mode"`.

## Build and install

```bash
./build.sh           # for Jellyfin 12.x   (needs the .NET 10 SDK)
./build.sh 10.11     # for Jellyfin 10.11.x (needs the .NET 9 SDK)
./build.sh both
```

The zip lands in `artifacts/`. Unpack it into `<config>/plugins/Audio Normalizer/` and
restart the server. Settings live at **Dashboard → Plugins → Audio Normalizer**.

You can also publish your own plugin repository on GitHub — push a `v1` tag and the workflow
builds, publishes and updates `manifest.json` for you, after which Jellyfin installs and
updates the plugin from its catalogue like any other.

Step by step, both routes: **[INSTALL.md](INSTALL.md)**.

## How to use it

1. Open the plugin settings. At the top is a **System status** panel showing the ffmpeg path,
   whether the required filters exist, and warnings — for example if your media folders are
   not writable.
2. Press **Measure the whole library**. Nothing is written to disk; this only collects numbers.
3. The **Media report** table fills in. The "Range" column is the quiet-to-loud spread for
   each film; anything from 18 LU is highlighted, because that is where dialogue drowns in
   explosions. Click a column heading to sort.
4. **Click a film's name** to expand it. Every audio track of that film is listed with its own
   measurements and a checkbox — tick the ones you want normalized. A film with Ukrainian,
   English and commentary tracks lets you pick exactly what you need. The choice saves
   immediately.
5. Then either **Build tracks where needed** in bulk, or the **Build** button on a single film.
6. In the player, switch the audio track to `AN - …`. The original stays where it was.

### Global and per-film

The settings page holds the global profile. Each row in the report also has:

- **Settings** — a per-film editor overriding any of the global values;
- **Exclude** — never touch this film;
- per-track checkboxes, plus a link back to the automatic choice.

Everything is available over the API too:

```bash
curl -X POST 'http://localhost:8096/AudioNormalizer/Tracks' \
  -H 'Authorization: MediaBrowser Token="YOUR_TOKEN"' \
  -H 'Content-Type: application/json' \
  -d '{"ItemId":"<id>","StreamIndexes":[1,3]}'
```

### The main thresholds

| Setting | What it is | Typical |
|---|---|---|
| Target loudness | the average level of the finished track | −16 LUFS |
| Maximum peak | the ceiling nothing goes above | −1.5 dBTP |
| Allowed range | how much dynamics to keep | 9 LU (night), 14 (cinematic) |
| Skip if range below | already-even audio gains nothing from a second track | 7 LU |

### Track naming

Generated tracks are called `AN - Ukrainian 5.1`: a configurable prefix followed by the
source track's own name, so they stand out in the player's audio list. Several tracks from
one film always get distinct file names.

## Problems handled up front

This isn't a list of assumptions — nearly every item was reproduced first and then fixed.

**1. `loudnorm` without an explicit sample rate inflates the file fourfold.**
The filter works at 192 kHz internally and leaves the output there. Measured: 69 MB instead
of 17 MB. The plugin always passes `-ar` and adds `aresample` at the end of the chain as a
second guard.

**2. A plain 5.1 → stereo downmix makes dialogue *quieter*.**
Measured: `-ac 2` dropped dialogue from −37.5 to −44.8 LUFS. So the default is a
dialogue-forward matrix with the centre lifted (+3 dB), surrounds pulled back (−3 dB) and
**LFE muted** — most of the "boom" lives in the subwoofer channel.

**3. That same matrix clips unless it's normalized.**
Unscaled coefficients measured 0.0 dBTP at the input and +6.2 dBTP after makeup gain. The
whole matrix is divided by the sum of its coefficients, which makes clipping arithmetically
impossible.

**4. Filter order decides everything.**
A compressor with an absolute threshold placed after an attenuated downmix does **nothing**
(measured: 23.9 LU, instead of any reduction at all). So window-based engines (`dynaudnorm`,
`speechnorm`) run **before** `loudnorm`, and the classic compressor runs **after**, once the
level is at target and a dBFS threshold means something.

**5. A plain compressor does not solve the problem.**
It only removes the loud parts and never lifts the quiet ones: 24 → 20 LU. Dialogue is no
more audible for it. The default engine is `dynaudnorm`, which pulls quiet passages up:
23.4 → 9.4 LU. The compressor remains as the gentlest option for people who want to keep
their dynamics.

**6. The peak ceiling was being breached slightly.**
`alimiter` limits sample peaks while the target is a *true* (inter-sample) peak. Measured: a
−1.5 dBFS limit produced −1.3 dBTP. A 0.3 dB margin was added; it now lands at −1.6.

**7. Encoder delay and lip sync.**
Measured by transient onset: AAC +21.3 ms, E-AC3 +5.3 ms, FLAC 0 ms. In every case the delay
is **correctly declared in the container** (`start_time = −0.021`), so a compliant player
compensates for it. If a particular client does not, there is a manual delay field, plus the
choice of FLAC (zero delay) or E-AC3.

**8. `.ac3` and `.m4a` lose metadata.**
Verified: a raw `.ac3` keeps neither language nor title; `.m4a` keeps language but loses the
title; `.mka` keeps both. Hence `.mka` is the default container.

**9. A temp file with an unfamiliar extension broke ffmpeg.**
The encode writes to `*.an-part` so Jellyfin never sees a half-written file. But ffmpeg
cannot infer a muxer from that extension and dies with `Unable to choose an output format`.
This bug was caught on a live run; the format is now passed explicitly with `-f`. The
finished file appears via an atomic rename inside the same folder.

**10. Jellyfin might not notice the new track.**
The discovery rules were read from the server's code: the file must sit **in the same folder**,
start with the video's name, be followed by a dot, and carry an extension from the audio list.
`ProbeProvider.HasChanged` separately compares the set of external audio files, which means a
cheap `Default` refresh is enough — no heavy re-fetch of metadata from the internet.
One important detail: the refresh uses a **fresh** `DirectoryService`, or the server works
from a cached folder listing and never sees the new file.

**11. A track name could vanish or turn into a flag.**
Jellyfin parses names by dots, and it does so in two different ways. `default`, `forced` and
`foreign` are matched **as substrings** — a track called "Forced English" would lose its whole
name and be marked forced. `cc`, `hi` and `sdh` are matched **exactly**. A two or three letter
word becomes the language. The plugin handles both rules: substring flags are stripped out of
the derived name ("Forced English" → `AN - English`), exact ones get a suffix. The code `hi`
(Hindi) collides with the hearing-impaired flag, so the language is always written `hin`.
Dots inside a name become hyphens, or they would slice it into pieces.

**11a. Several tracks of one film must not overwrite each other.**
Names are allocated from a set that is unique within the film; on a collision the stream index
is appended. Verified on a film with two identically named English tracks.

**12. Normalizing something already normalized.**
External tracks are never offered as a source, so a second pass cannot feed the plugin its own
output.

**13. Commentary tracks.**
Tracks whose name matches `commentary`, `director`, audio description and similar are filtered
out of the automatic choice — otherwise the director's commentary could become the basis.

**14. A read-only media folder.**
Jellyfin looks for external audio **only** next to the video, so for such a library the whole
approach cannot work. The plugin checks for write permission in advance — both in diagnostics
and before every job — and says so plainly instead of failing with a permission error halfway
through.

**15. Disk space.**
Before each job the output size is estimated and free space is checked with a margin
(5 GB by default). There is a per-run size cap as well.

**16. Server load.**
A queue with a concurrency limit, `nice`, and a pause while somebody is watching. Plus a dry
run mode that only reports what it would do.

**17. Interrupted and hung jobs.**
A timeout proportional to the film's length, proper killing of the process tree, and cleanup
of partial files. Cancelling never leaves debris behind.

**18. Repeated work.**
Per-item state (source size and timestamp, a fingerprint of the settings) lives in
`state.json`. If the settings or the source file changed, the track is rebuilt; if not, it is
skipped. The file is written atomically, and if it is ever corrupted it is moved aside and
work starts from a clean slate rather than the plugin failing to load.

**19. Orphaned tracks.**
A separate scheduled task removes generated files whose film has disappeared. **Only** paths
the plugin itself recorded as its own output are ever deleted.

**20. Silent or empty tracks.**
If `loudnorm` measures `-inf` (silence) the result is treated as unusable and the second pass
does not apply nonsensical gain.

**21. Paths with spaces, brackets and Cyrillic.**
Arguments go through `ArgumentList` — never joined into a string, never through a shell.
Verified on a folder named `Дюна (2021)` holding `Дюна (2021) [2160p].mkv`.

**22. Unusual ffmpeg builds.**
The server's own ffmpeg is used (`IMediaEncoder.EncoderPath`), not the system one. Each
filter's availability is checked, and diagnostics show what is missing.

**23. Measuring several tracks at once.**
Measuring every track of a film in one ffmpeg call saves a decode per track, but ffmpeg prints
the summaries in completion order, not graph order — observed 0, 2, 1 on a three-track file.
Results are matched by the index in `Parsed_ebur128_N`, never by position.

## Honest limitations

- **This takes time.** On the test machine processing ran roughly 13–16× faster than realtime,
  so a two-hour film is about 15–20 minutes (analysis plus encode). A 500-film library means
  days of background work. That is why the queue, the pause during playback and the saved
  state are not decoration.
- **An external track disables container direct play.** To serve video together with external
  audio the server has to remux them. The video is copied without re-encoding, so the load is
  small, but not zero.
- **Disk space.** AAC at 256 kbps is roughly 220 MB for a two-hour film. FLAC is 3–5× that.
- **Automatic strength is a heuristic.** The table mapping "how much to compress" onto the `m`
  parameter was measured on a single synthetic clip. It is monotonic and behaves sensibly, but
  it does not guarantee hitting the requested range exactly. That is precisely why the report
  shows the measured range per film, so you can override it.
- **5.1 output slightly breaches the ceiling** (−1.3 instead of −1.5 dBTP): the limiter works
  per channel while the measurement is of the downmix. The default stereo mode is within range.
- The plugin leaves music alone — films and episodes only.

## API

Every endpoint requires administrator rights.

| Method | Path | Purpose |
|---|---|---|
| GET | `/AudioNormalizer/Report?onlyProblems=true` | per-item report, including every track |
| GET | `/AudioNormalizer/Status` | queue status |
| GET | `/AudioNormalizer/Diagnostics` | ffmpeg, filters, warnings |
| GET | `/AudioNormalizer/SelfTest/{itemId}` | full dry self-test on one film |
| GET | `/AudioNormalizer/Libraries` | libraries, for a picker |
| POST | `/AudioNormalizer/Analyze` | queue measurement |
| POST | `/AudioNormalizer/Generate` | queue generation |
| POST | `/AudioNormalizer/Cancel` | empty the queue |
| POST | `/AudioNormalizer/Tracks` | choose which audio tracks of an item to normalize |
| POST | `/AudioNormalizer/Override` | per-item profile or exclusion |
| GET | `/AudioNormalizer/Override/{itemId}` | the effective profile for an item |
| DELETE | `/AudioNormalizer/Track/{itemId}?streamIndex=N` | delete a generated track |

Scheduled tasks (Dashboard → Scheduled Tasks): "Measure audio loudness",
"Build normalized audio tracks", "Remove orphaned normalized tracks".
