# CLAUDE.md

Context for continuing this project. Claude Code reads this file automatically, so a new
session starts with everything below and does not need the original conversation.

Everything is written in English: code, comments and documentation. The one exception is
the plugin's user-facing settings page (`configPage.html` / `configPage.js`), whose visible

---

## What this is

A Jellyfin plugin that fixes the "explosions too loud, dialogue too quiet" problem by
generating a **second, loudness-normalized audio track** next to each film. The original
file is never modified; the viewer switches audio tracks in the player.

Also ships `tools/normalize-library.sh`, the same pipeline as a standalone bash script
for people who do not want to build a plugin.

## Status: what is verified and what is not

**Read this before assuming anything works.**

### Verified by actually running it

- The whole ffmpeg pipeline, against real audio, with measured before/after numbers.
- The chains were generated by the plugin's own `FilterChainBuilder`, driven through a
  test harness (`build/harness/`), not typed by hand. All six engine × downmix
  combinations produce valid ffmpeg runs.
- `tools/normalize-library.sh` ran a full cycle on a test library with Cyrillic paths:
  created the track, skipped an already-flat film, and did nothing on a second run.
- The plugin compiles clean, zero warnings.

### NOT verified

**The plugin has never been compiled against the real Jellyfin NuGet packages.** The
environment it was written in had no access to nuget.org, so it was type-checked against
hand-written stubs in `build/stubs/Stubs.cs`, derived from the real Jellyfin 12.1 source
(branch `release-12.z`). Every signature used was read from that source, but a real build
has not happened.

**So the first real task is: build it and fix whatever the compiler says.** See
"First build" below. The audio side is sound; the integration layer is the unproven part.

### Measured results (test mix: quiet centre dialogue, loud LFE explosions)

## Hard-won facts — do not "simplify" these away

Each of these was reproduced, measured, and then fixed. Changing them will silently
regress the output.

1. **`-ar` is mandatory.** Left alone, `loudnorm` resamples its output to 192 kHz; the
   file came out 4× larger (69 MB vs 17 MB). The chain also ends with `aresample` as a
   second guard.

2. **Filter order is load-bearing.** Window-based dynamics (`dynaudnorm`, `speechnorm`) go
   **before** `loudnorm` because they are level-independent. A classic compressor goes
   **after**, because its threshold is absolute dBFS and is meaningless against an
   attenuated downmix — measured: the same compressor placed before did nothing at all
   (range 23.9 LU instead of any reduction).

3. **A plain compressor does not solve the problem.** It only pulls loud parts down
   (24 → 20 LU) and never makes dialogue audible. `dynaudnorm` lifts quiet passages:
   23.4 → 9.4 LU at m=8. That is why Dynaudnorm is the default engine.

4. **The downmix matrix must be scaled by the sum of its coefficients.** Unscaled, it
   clipped: 0.0 dBTP at the input and +6.2 dBTP after makeup gain.

5. **Default `-ac 2` makes dialogue worse**, −37.5 → −44.8 LUFS. Hence the
   dialogue-forward matrix with LFE muted by default.

6. **`alimiter` limits sample peaks, the target is true peak.** Limiting at exactly
   −1.5 dBFS measured −1.3 dBTP, so `TruePeakSafetyDb = 0.3` exists in
   `FilterChainBuilder`. Do not remove it.

7. **The temp file needs an explicit `-f` muxer.** Output goes to `*.an-part` so a
   half-written file is never scanned, but ffmpeg cannot infer a format from that
   extension and dies with "Unable to choose an output format".

8. **Every ffmpeg call needs `-nostdin`.** A call without it inside a loop whose stdin is
   a file list will swallow that list and hang. This actually happened in the bash script.

9. **Encoder delay, measured by transient onset:** AAC +21.3 ms, E-AC3 +5.3 ms, FLAC 0 ms.
   All correctly declared in the container (`start_time = −0.021`), so a compliant player
   compensates. `ManualDelayMs` exists for clients that do not.

10. **Container metadata:** raw `.ac3` carries no language or title; `.m4a` keeps language
    but drops title; `.mka` keeps both. Hence `.mka` is the default.

### Jellyfin-specific rules, read out of the server source

11. **External audio discovery** (`Emby.Naming/ExternalFiles/ExternalPathParser.cs`,
    `MediaBrowser.Providers/MediaInfo/MediaInfoResolver.cs`): the file must sit in the
    same folder as the video, start with the video's filename-without-extension, be
    followed by `.` (the only delimiter Jellyfin defines), and have an extension from
    `NamingOptions.AudioFileExtensions`.

12. **Reserved words in the name, and the two different match rules.** Jellyfin parses
    dot-separated pieces. `default`, `forced` and `foreign` are matched with **Contains**,
    so a title merely *containing* one of them is turned into a flag and the whole piece
    disappears from the displayed name. `cc`, `hi` and `sdh` are matched with **Equals**,
    so only a piece that is exactly one of them counts. A 2–3 letter word becomes the
    language. `OutputNaming` handles both rules: substring flags are stripped out of the
    derived name, exact flags get "-track" appended. `hi` (Hindi) collides with the
    hearing-impaired flag, so the language is always written `hin`.
    Verified in `Emby.Naming/ExternalFiles/ExternalPathParser.cs:86,94,121`.

16. **Several tracks can be normalized per film**, so their file names must differ from
    each other. `OutputNaming.BuildOutputPath` takes a `takenNames` set per item and falls
    back to the stream index on a collision. The same set is used by the report so the UI
    shows exactly the names the player will.

17. **ffmpeg prints multi-filter summaries out of order.** Measuring several tracks in one
    invocation is worth it (one decode, not N), but the summaries come back in completion
    order: observed 0, 2, 1 on a three-track file. `ParseEbur128Multi` keys on the number
    in `Parsed_ebur128_N`, never on position.

13. **A cheap `Default` refresh is enough.** `ProbeProvider.HasChanged` explicitly compares
    the set of external audio files against `video.AudioFiles`, so no expensive
    `FullRefresh` (and no remote metadata lookups) is needed.

14. **The refresh needs a FRESH `DirectoryService`.** The resolver reads the folder listing
    with `clearCache: false`; a reused instance would not contain the file just written.

15. **Manifest version scheme.** The server keeps entries with `targetAbi <= its version`,
    then installs the **highest plugin version** left, and never checks which .NET the DLL
    targets. So the newer-server build must carry the higher version:
    `1.0.0.x` / targetAbi `10.11.0.0` for Jellyfin 10.11, `2.0.0.x` / `12.0.0.0` for 12.
    Break this and a Jellyfin 12 box installs the net9.0 assembly; it fails loudly at load
    (`Failed to load assembly ... Disabling plugin`) rather than misbehaving.

## Testing without a Jellyfin server

The harness drives the real `FilterChainBuilder`, so what gets tested is shipped code:

```bash
cd build/harness
H="dotnet run -c Release -p:UseJellyfinStubs=true --no-build --"

$H chain 6 25.4                 # the encode chain for a 5.1 source with LRA 25.4
$H analysis 6 25.4              # the single-decode analysis graph
$H gain 6 22                    # what auto-strength resolves to
$H nametest                     # title sanitising against Jellyfin's reserved words
$H cmd 6 25.4 Dynaudnorm 9 auto DialogueStereo /path/to/film.mkv   # pasteable command
```

To make a test file with quiet dialogue and loud explosions, and to measure results:
`ffmpeg -af ebur128=peak=true:framelog=quiet -f null -`
and read `I`, `LRA`, `True peak` from the summary.

## Conventions

- Nullable enabled. Analyzers on at `Recommended`, with `CA1848;CA1873;CA1711;CA1861`
  suppressed in the csproj (logging-performance and naming noise, not useful here).
- No StyleCop; one type per file is preferred but not enforced.
- Comments explain **why**, especially where a measurement drove the choice. Do not strip
  those — they are the reason the pipeline works.
- Documentation, code, identifiers, log messages and XML docs: English. Only the config
  page's visible strings are Ukrainian.
- Two deliberate exceptions where Cyrillic is data rather than prose, and must stay:
  `PluginConfiguration.CommentaryKeywords` carries Ukrainian words ("описов",
  "тифлокоментар") so Ukrainian commentary tracks are detected, and the naming tests in
  `build/harness` use a Cyrillic title to prove the sanitizer handles non-Latin names.
- `ProcessStartInfo.ArgumentList`, never a joined command string — paths contain spaces,
  brackets and Cyrillic.

## Open work, roughly in priority order

1. **Build against real packages and fix the fallout.** The only blocking task.
2. Test on a real library: does the generated track actually appear in the player after
   the automatic refresh? This is the highest-risk untested integration point.
3. ~~Per-item override editing in the UI.~~ Done: the report's per-film settings button opens
   an editor built from `OVERRIDE_FIELDS` in `configPage.js`. Track title is deliberately
   left out of it, so one library does not end up with differently named tracks.
4. Per-item track selection is stored in `ItemProfileOverride.SelectedStreamIndexes` with
   `HasExplicitTrackSelection` to tell "user picked nothing" from "user has not looked".
   Worth a pass to confirm the config file stays tidy when many films get selections.
5. The auto-strength mapping in `FilterChainBuilder.ResolveMaxGain` is a table fitted to
   **one** synthetic clip. It is monotonic and behaves sensibly, but it does not guarantee
   hitting the requested range. Re-fit it against a few real films.
6. 5.1 output (`KeepLayout`) slightly overshoots the ceiling: −1.3 dBTP against a −1.5
   target, because the limiter works per channel while measurement is of the downmix.
7. Progress reporting for the encode pass is wired but only lightly exercised.
8. Nothing is unit-tested. A test project around `FilterChainBuilder`, `OutputNaming` and
   `FfmpegOutputParser` would be cheap and worthwhile — they are all pure functions.
